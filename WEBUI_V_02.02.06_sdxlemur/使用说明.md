# WEBUI_V_02.02.06（sdxlemur / FM160）使用说明

## 1. 项目作用

从 `160/sdxlemur-sysfs.ubi` 中提取的原厂 WebUI 组件，按设备原始绝对路径还原在 `rootfs/` 下，可通过 adb 直接部署到模组：

- 前端：`/webs/web`（91 个文件，Vue + Element 单页应用）；
- 服务端：`/usr/bin/webs`（GoAhead）+ `/usr/bin/libgo.so`（Fibocom 定制后端，提供 `/fibo/webapi`、`/fibo/fibologin`）；
- 依赖：`libfibosocket.so.0`、`libfibo_utils.so.0`；
- 启动：systemd `webs.service`，监听 80/443。

详细文件清单与来源分析见 [WEBUI_V_02.02.06_移植说明.md](./WEBUI_V_02.02.06_移植说明.md)。

## 2. 适用模组

| 模组 / 平台 | 是否适用 | 说明 |
|---|---|---|
| FM160（sdxlemur） | 可用 | 与组件同平台，可直接部署/替换 |
| 160WAU（sdxlemur） | 可用 | 会以本版登录流程/页面集合替换原定制版本 |
| FM150AE（sdxprairie） | 不可用 | 两代 Fibo 软件栈不同，`libgo`/`webs` 与 `/fibo/webapi` 命令集不匹配；该平台本身也没有 `/webs` |
| 其他 ARM32 模组 | 一般不可用 | 除架构外还必须是 sdxlemur 底座并具备依赖服务/库 |

> 本包面向 **ARM 32 位（armv7l）**，且目标必须已有 `init_sys_mss.service`、`ipacm.service`、`netmgrd.service` 等底座服务。

## 3. 前置条件

1. `adb devices` 可见设备并已授权，`adb root` 可用。
2. 根分区可写（overlay / remount rw），`/webs`、`/usr/bin`、`/usr/lib`、`/etc/initscripts` 可写。
3. 目标 80/443 未被子系统长期占用；若已有 lighttpd，脚本会先停止它。
4. 目标 glibc / systemd 满足要求（详见移植说明第 9 节）。

## 4. 使用方法

### 4.1 一键部署（推荐）

在 Windows 的 `WEBUI_V_02.02.06_sdxlemur` 目录：

- 双击 `双击运行_上传WEBUI.bat`；或执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\adb_push_webui.ps1
```

如需指定 adb 路径：

```powershell
$env:ADB = "C:\platform-tools\adb.exe"
powershell -ExecutionPolicy Bypass -File .\adb_push_webui.ps1
```

脚本流程：

1. `adb root`、`remount`，申请写权限；
2. 备份现有 `/webs`、`/usr/bin/webs`、`/usr/bin/libgo.so`、依赖库到 `/data/*.<时间戳>`；
3. 创建目标目录；
4. 逐文件推送 `rootfs` 到原始绝对路径（约 110 个文件，避免目录推送多一层）；
5. 重建符号链接：
   - `/usr/lib/libfibosocket.so.0`
   - `/usr/lib/libfibo_utils.so.0`
   - `/lib/systemd/system/multi-user.target.wants/webs.service`
6. 恢复权限（`/webs` 统一 0755，程序/脚本 0755，unit 0644）与属主 `root:root`；
7. 停止 lighttpd，`systemctl enable/restart webs.service`，并打印版本、进程与端口。

### 4.2 手动部署要点

```bash
adb root && adb remount
adb shell "ts=$(date +%Y%m%d_%H%M%S); cp -a /webs /data/webs.bak.$ts 2>/dev/null; cp -a /usr/bin/webs /data/webs.bin.$ts 2>/dev/null; cp -a /usr/bin/libgo.so /data/libgo.so.$ts 2>/dev/null"
adb push rootfs/webs /webs
adb push rootfs/usr/bin/webs /usr/bin/webs
adb push rootfs/usr/bin/libgo.so /usr/bin/libgo.so
adb push rootfs/usr/lib/libfibosocket.so.0.0.0 /usr/lib/libfibosocket.so.0.0.0
adb push rootfs/usr/lib/libfibo_utils.so.0.0.0 /usr/lib/libfibo_utils.so.0.0.0
adb push rootfs/etc/initscripts/start-webs /etc/initscripts/start-webs
adb shell "ln -sf libfibosocket.so.0.0.0 /usr/lib/libfibosocket.so.0; ln -sf libfibo_utils.so.0.0.0 /usr/lib/libfibo_utils.so.0"
adb shell "systemctl stop lighttpd 2>/dev/null; systemctl daemon-reload; systemctl enable webs.service; systemctl restart webs.service"
```

重启后浏览器访问 `http://<模组IP>/` 或 `https://<模组IP>/`。

## 5. 验证

```bash
adb shell "cat /webs/web/webui_version"          # 应为 WEBUI_V_02.02.06
adb shell "pidof webs"
adb shell "netstat -lntp | grep -E ':80|:443'"
```

页面能打开、登录后能显示设备信息，说明 `libgo.so` 与底座服务正常。

## 6. 回滚

```bash
adb shell "rm -rf /webs && cp -a /data/webs.bak.<时间戳> /webs"
adb shell "cp -a /data/webs.bin.<时间戳> /usr/bin/webs"
adb shell "cp -a /data/libgo.so.<时间戳> /usr/bin/libgo.so"
adb shell "systemctl restart webs.service"
```

## 7. 注意事项

1. 不要与 `WEBUI_V_02.02.10`（含 fibologin 的通用版）或 `WEBUI_V_02.02.28`（lighttpd 版）混用文件，前端分包哈希与服务端接口必须整套匹配。
2. `webs` 固定占用 80/443；目标若运行 lighttpd，必须先停止/禁用。
3. `/webs` 需要可写；只读固件请使用 overlay 或把站点放到可写分区后绑定挂载。
4. 本版依赖 `/usr/lib/libfibosocket.so.0` 与 `libfibo_utils.so.0`，不要只推送站点文件。
5. 来源为调试镜像，证书与权限较宽松，量产环境应替换证书并收紧权限。
6. 若目标为 FM150AE，请勿直接使用；可参考 `fibocom-webui-inmodem` 或针对 sdxprairie 的专用包。
