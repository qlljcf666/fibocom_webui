# WEBUI_V_02.02.10（sdxlemur-sysfs.ubi）使用说明

## 1. 项目作用

从 UBI 镜像 `sdxlemur-sysfs.ubi` 中提取的原厂 WebUI 组件，版本 **WEBUI_V_02.02.10**，按设备绝对路径还原在 `rootfs/` 下：

- 服务端：`/usr/bin/webs`（GoAhead）+ `/usr/bin/libgo.so`（提供 `/fibo/webapi` 与 `/fibo/fibologin`）；
- 依赖：`libfibosocket.so.0`、`libfibo_utils.so.0`、底座 `ipacm/netmgrd/init_sys_mss` 服务；
- 前端：`/webs/web`（84 个文件，含 fibologin 登录流程）；
- 启动：systemd `webs.service`，监听 80/443。

详细清单见 [WEBUI_V_02.02.10_移植说明.md](./WEBUI_V_02.02.10_移植说明.md)、[160wau-sdxlemur_兼容性分析.md](./160wau-sdxlemur_兼容性分析.md)、[150-sdxprairie_兼容性分析.md](./150-sdxprairie_兼容性分析.md)。

## 2. 适用模组

| 模组 / 平台 | 是否适用 | 说明 |
|---|---|---|
| FM160（sdxlemur） | 可用（整包替换） | 与组件同平台；相对 160WAU 定制版会改变登录流程与页面集合，部分 AU 定制功能可能缺失 |
| 160WAU（sdxlemur） | 实验可用 | 建议仅整目录替换并完整备份；页面由 125 变为 84，可能缺少定制页面 |
| FM150AE（sdxprairie） | 不可直接用 | 结论为“不能直接 adb 上传后正常运行”：两代 Fibo 软件栈、`/fibo` 命令集、数据模型不匹配，且目标无 `/webs`、SELinux 为 Enforcing；仅可实验，不建议量产 |

> 本包是 **WEBUI_V_02.02.10 + GoAhead**，与 `WEBUI_V_02.02.28 + lighttpd`、160WAU 双构建版均不是同一套，不能混用。

## 3. 前置条件

1. `adb root` 与 `remount` 可用，`/webs`、`/usr/bin`、`/usr/lib`、`/etc/initscripts` 可写。
2. 目标已有 `init_sys_mss.service`、`ipacm.service`、`netmgrd.service`、`persist-mount.service` 等底座服务。
3. 80/443 空闲；若已有 lighttpd，脚本会先停止。
4. `/usr/lib/libfibosocket.so.0`、`/usr/lib/libfibo_utils.so.0` 符号链接可重建。

## 4. 使用方法

在 Windows 的 `WEBUI_V_02.02.10_ubi` 目录：

- 双击 `双击运行_上传WEBUI.bat`；或：

```powershell
powershell -ExecutionPolicy Bypass -File .\adb_push_webui.ps1
```

脚本流程：

1. 申请 root/写权限；
2. 备份 `/webs`、`/usr/bin/webs`、`/usr/bin/libgo.so`、`/usr/lib/libfibosocket.so.0.0.0` 到 `/data/*.<时间戳>`；
3. 创建 `/webs/web/{css,js,json,static/{fonts,img}}` 等目录；
4. 逐文件推送 `rootfs`（约 102 个文件）；
5. 重建符号链接（`libfibosocket.so.0`、`libfibo_utils.so.0`、`multi-user.target.wants/webs.service`）；
6. 恢复权限/属主（`/webs` 0755、程序 0755、unit 0644、`root:root`）；
7. 停止 lighttpd，`daemon-reload`、`enable`、`restart webs.service`，并打印版本/进程/端口。

### 手动部署关键步骤

```bash
adb root && adb remount
adb shell "ts=$(date +%Y%m%d_%H%M%S); cp -a /webs /data/webs.bak.$ts 2>/dev/null; cp -a /usr/bin/webs /data/webs.bin.$ts 2>/dev/null; cp -a /usr/bin/libgo.so /data/libgo.so.$ts 2>/dev/null"
adb push rootfs/webs /webs
adb push rootfs/usr/bin/webs /usr/bin/webs
adb push rootfs/usr/bin/libgo.so /usr/bin/libgo.so
adb push rootfs/usr/lib/libfibosocket.so.0.0.0 /usr/lib/libfibosocket.so.0.0.0
adb push rootfs/usr/lib/libfibo_utils.so.0.0.0 /usr/lib/libfibo_utils.so.0.0.0
adb shell "ln -sf libfibosocket.so.0.0.0 /usr/lib/libfibosocket.so.0; ln -sf libfibo_utils.so.0.0.0 /usr/lib/libfibo_utils.so.0"
adb shell "systemctl stop lighttpd 2>/dev/null; systemctl daemon-reload; systemctl enable webs.service; systemctl restart webs.service"
```

## 5. 验证

```bash
adb shell "cat /webs/web/webui_version"     # 应为 WEBUI_V_02.02.10
adb shell "grep -o 'index\\.[0-9]*\\.js' /webs/web/index.html | head -1"
adb shell "pidof webs"
adb shell "netstat -lntp | grep -E ':80|:443'"
```

登录页可正常登录、首页能加载设备信息，说明 fibologin 与 webapi 后端正常。

## 6. 回滚

```bash
adb shell "rm -rf /webs && cp -a /data/webs.bak.<时间戳> /webs"
adb shell "cp -a /data/webs.bin.<时间戳> /usr/bin/webs"
adb shell "cp -a /data/libgo.so.<时间戳> /usr/bin/libgo.so"
adb shell "systemctl restart webs.service"
```

## 7. 注意事项

1. 必须整套替换 `/webs` + `webs` + `libgo.so` + `route.txt`；只换前端会因缺少 `websFiboLoginOpen` 导致登录失败。
2. 目标不能有旧版本残留文件，否则目录混杂、排障困难；建议先整目录备份再替换。
3. 本包端口固定 80/443，与 lighttpd 冲突时需先停用。
4. FM150AE（sdxprairie）平台只能做实验性验证，需临时 permissive SELinux，且接口命令集不同，功能完整性无法保证；不建议量产。
5. 包元数据标注 glibc >= 2.31，但实测 2.28 可加载；仍建议按实机验证。
6. 若目标是没有原厂 Web 栈的模组，建议改用 `fibocom-webui-inmodem`。
