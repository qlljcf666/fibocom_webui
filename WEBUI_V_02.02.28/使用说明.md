# WEBUI_V_02.02.28（lighttpd）使用说明

## 1. 项目作用

从 `160/system.img`（ext4，sdxlemur 平台）中提取的原厂 WebUI 组件，版本 **WEBUI_V_02.02.28**，按设备绝对路径还原在 `rootfs/` 下：

- 前端：`/webs/web`（104 个文件，Vue + Element 单页应用，含登录页、品牌图、权限菜单）；
- 服务端：`/usr/sbin/lighttpd` / `lighttpd-angel`（ARM32）+ `/data/lighttpd.conf`；
- 启动：`/etc/initscripts/lighttpd` 与 `lighttpd.service`，监听 80/443，自动生成自签证书；
- **不包含业务后端**：`/fibo/webapi` 由底座固件的 QCMAP Web 后端（`/usr/bin/QCMAP_Web_CLIENT` 等）提供。

详细文件清单见 [WEBUI_V_02.02.28_移植说明.md](./WEBUI_V_02.02.28_移植说明.md)。

## 2. 适用模组

| 模组 / 平台 | 是否适用 | 说明 |
|---|---|---|
| FM150AE | 有条件可用 | 组件文档标称适用，但**目标必须已有 QCMAP Web 后端**，否则页面能开、接口全失败 |
| FM160（sdxlemur） | 有条件可用 | 同上；适合已有 02.02.28 + lighttpd 底座的产品做界面整包恢复 |
| 无 QCMAP 后端的模组 | 不可用 | 本包只有前端与 lighttpd；请改用 `fibocom-webui-inmodem`（自带 Go 后端） |
| 其他非 ARM32 平台 | 不可直接用 | lighttpd 为 ARM32 动态二进制；可只推 `/webs/web` 并用目标自带 Web 服务器 |

> 关键判断：目标上是否存在 `/usr/bin/QCMAP_Web_CLIENT`、`/dev/socket/data/www/qcmap_cgi_webclient_file`，以及 `/data/www` 下的会话文件。缺一不可。

## 3. 前置条件

1. `adb root`、`remount` 可用；`/webs`、`/usr/sbin`、`/data`、`/etc/initscripts` 可写。
2. 80/443 空闲；若已有其他 Web 服务，需先停止或改用其他端口。
3. `/data` 必须可写（证书、会话、备份都在这里）。
4. 目标 glibc/libcrypto/libpcre2 等依赖满足（见移植说明第 9 节）。

## 4. 使用方法

### 4.1 一键部署

在 Windows 的 `WEBUI_V_02.02.28` 目录：

- 双击 `双击运行_adb_push_webui.bat`；或：

```powershell
powershell -ExecutionPolicy Bypass -File .\adb_push_webui.ps1
```

指定 adb 路径：

```powershell
$env:ADB = "C:\platform-tools\adb.exe"
powershell -ExecutionPolicy Bypass -File .\adb_push_webui.ps1
```

脚本流程：

1. `adb root`、`remount`，申请写权限；
2. 备份 `/webs/web` 和 `/data/lighttpd.conf` 到 `/data/*.<时间戳>`；
3. 创建 `/webs/web`、`/etc/initscripts`、`/etc/lighttpd`、`/usr/sbin` 等目录；
4. 逐文件推送 `rootfs`（114 个文件，直接还原绝对路径）；
5. 恢复原厂权限：`/webs/web` 全部 `0755`，脚本/程序 `0755`，unit/preset `0644`；
6. 恢复属主 `root:root`；
7. `systemctl daemon-reload`，`enable` 并 `restart lighttpd.service`；无 systemd 时调用 `/etc/initscripts/lighttpd restart`。

### 4.2 手动部署关键步骤

```bash
adb root && adb remount
adb shell "ts=$(date +%Y%m%d_%H%M%S); cp -a /webs/web /data/webs_web.bak.$ts 2>/dev/null; cp -a /data/lighttpd.conf /data/lighttpd.conf.bak.$ts 2>/dev/null"
adb push rootfs/webs/web /webs/web
adb push rootfs/data/lighttpd.conf /data/lighttpd.conf
adb push rootfs/etc/initscripts/lighttpd /etc/initscripts/lighttpd
adb push rootfs/usr/sbin/lighttpd /usr/sbin/lighttpd
adb push rootfs/usr/sbin/lighttpd-angel /usr/sbin/lighttpd-angel
adb push rootfs/lib/systemd/system/lighttpd.service /lib/systemd/system/lighttpd.service
adb shell "chmod -R 0755 /webs/web; chmod 0755 /etc/initscripts/lighttpd /data/lighttpd.conf /usr/sbin/lighttpd /usr/sbin/lighttpd-angel"
adb shell "chown -R root:root /webs/web /data/lighttpd.conf /usr/sbin/lighttpd /usr/sbin/lighttpd-angel /etc/initscripts/lighttpd"
adb shell "systemctl daemon-reload; systemctl enable lighttpd.service; systemctl restart lighttpd.service"
```

登录页可访问 `http://<模组IP>/`，启用 443 时也可用 `https://<模组IP>/`。

## 5. 验证

```bash
adb shell "cat /webs/web/webui_version"     # 应为 WEBUI_V_02.02.28
adb shell "pidof lighttpd"
adb shell "netstat -lntp | grep -E ':80|:443'"
```

- 能打开登录页：前端与 lighttpd 正常。
- 登录成功且首页有设备信息：QCMAP Web 后端与 `/fibo/webapi` 正常。
- 若登录一直失败或页面数据全空，优先检查 `/usr/bin/QCMAP_Web_CLIENT` 与 `/dev/socket/data/www/qcmap_cgi_webclient_file`。

## 6. 回滚

```bash
adb shell "rm -rf /webs/web && cp -a /data/webs_web.bak.<时间戳> /webs/web"
adb shell "cp -a /data/lighttpd.conf.bak.<时间戳> /data/lighttpd.conf"
adb shell "systemctl restart lighttpd.service"
adb shell "chmod -R 0755 /webs/web"
```

## 7. 注意事项

1. **没有后端不要单装本包**：它只是前端 + lighttpd。没有 QCMAP Web 后端的模组请使用 `fibocom-webui-inmodem`。
2. 所有 Web 文件原厂打包为 `0755`，移植时保持一致；不要改成 0644。
3. `/data` 必须可写：HTTPS 证书、会话、备份都依赖它。
4. 端口默认 80/443；与 webs/goahead 冲突时先停用对方。
5. 不要覆盖产品专属的 `/data/lighttpd.conf`：若目标端口、站点根、证书路径不同，先比对再合并。
6. 若目标是 aarch64 且没有 32 位运行库，只推送 `/webs/web` 与配置，保留目标自带 lighttpd。
7. 菜单是 Fibocom 多产品共用（含 Ethernet/WLAN/W5G 等），目标无对应硬件时可通过 `permission.json` 隐藏。
8. 前端主 JS 内含 FG360 的 FOTA 测试地址，启用升级功能前需替换为目标产品地址。
9. 自签证书仅用于调试，正式产品应替换。
10. 不要删除 `/webs/web/webui_version`，固件通过它识别 WebUI 版本。
