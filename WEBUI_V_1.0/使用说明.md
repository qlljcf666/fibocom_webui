# WEBUI_V_1.0（160WAU / sdxlemur）使用说明

## 1. 项目作用

从 `160wau-sdxlemur-sysfs.ubi` 中提取的 **160WAU 定制 WebUI**，按设备绝对路径还原在 `rootfs/` 下：

- 前端：`/webs/web`（125 个文件；JS 为现代浏览器 `1677576251596` 与旧浏览器 `1677576217580` 双构建，各 48 个文件）；
- 服务端：`/usr/bin/webs`（GoAhead）+ `/usr/bin/libgo.so`（仅导出 `websFiboapiOpen`，**没有** `/fibo/fibologin`）；
- 依赖：`libfibosocket.so.0`、`libfibo_utils.so.0`；
- 启动：systemd `webs.service`，监听 80/443；
- 镜像内没有 `webui_version` 文件，版本以构建号识别。

详细文件清单见 [WEBUI_160WAU_sdxlemur_移植说明.md](./WEBUI_160WAU_sdxlemur_移植说明.md)。

## 2. 适用模组

| 模组 / 平台 | 是否适用 | 说明 |
|---|---|---|
| FM160（sdxlemur，FM160W-AU 构建） | 可用 | 与组件同平台，最匹配 |
| 160WAU（sdxlemur） | 可用 | 原定制版本，可直接恢复 |
| FM150AE（sdxprairie） | 不可用 | 旧平台 `libgo`/`webs` 栈与 `/fibo/webapi` 命令集不同，登录与数据大概率失败；该平台也没有 `/webs` |
| 其他平台 | 一般不适用 | 需要 sdxlemur 底座与 Fibo 依赖库 |

## 3. 前置条件

1. `adb root`、`remount` 可用；`/webs`、`/usr/bin`、`/usr/lib`、`/etc/initscripts` 可写。
2. 目标已有 `init_sys_mss.service`、`ipacm.service`、`netmgrd.service` 等底座服务。
3. 80/443 空闲；若运行 lighttpd，脚本会先停止。
4. 支持双构建浏览器（现代/旧浏览器）；访问设备需与目标浏览器能力匹配。

## 4. 使用方法

在 Windows 的 `WEBUI_V_1.0` 目录：

- 双击 `双击运行_上传WEBUI.bat`；或：

```powershell
powershell -ExecutionPolicy Bypass -File .\adb_push_webui.ps1
```

脚本流程：

1. 申请 root/写权限；
2. 备份现有 `/webs`、`/usr/bin/webs`、`/usr/bin/libgo.so`、依赖库到 `/data/*.<时间戳>`；
3. 创建 `/webs/web/{js,json,static/{css,fonts,img}}` 等目录；
4. 逐文件推送 `rootfs`（约 144 个文件）；
5. 重建符号链接（`libfibosocket.so.0`、`libfibo_utils.so.0`、`webs.service`）；
6. 恢复权限/属主（`/webs` 0755、程序 0755、unit 0644、`root:root`）；
7. 停止 lighttpd，`systemctl daemon-reload`、`enable`、`restart webs.service`，并打印构建号/进程/端口。

### 手动部署关键步骤

```bash
adb root && adb remount
adb shell "ts=$(date +%Y%m%d_%H%M%S); cp -a /webs /data/webs.bak.$ts 2>/dev/null; cp -a /usr/bin/webs /data/webs.bin.$ts 2>/dev/null; cp -a /usr/bin/libgo.so /data/libgo.so.$ts 2>/dev/null"
adb push rootfs/webs /webs
adb push rootfs/usr/bin/webs /usr/bin/webs
adb push rootfs/usr/bin/libgo.so /usr/bin/libgo.so
adb push rootfs/usr/lib/libfibosocket.so.0.0.0 /usr/lib/libfibosocket.so.0.0.0
adb push rootfs/usr/lib/libfibo_utils.so.0.0.0 /usr/lib/libfibo_utils.so.0.0.0
adb shell "ln -sf libfibosocket.so.0.0.0 /usr/lib/libfibosocket.so.0; ln -sf libfibo_utils.so.0.0.0 /usr/lib/libfibo_utils.so.0"
adb shell "systemctl stop lighttpd 2>/dev/null; systemctl daemon-reload; systemctl enable webs.service; systemctl restart webs.service"
```

## 5. 验证

```bash
adb shell "ls /webs/web/js | head"
adb shell "pidof webs"
adb shell "netstat -lntp | grep -E ':80|:443'"
```

- 前端入口应引用构建号 `1677576251596`（现代）与 `1677576217580`（旧浏览器）。
- 页面能打开且能加载数据，说明 `webs` + `libgo.so` 与底座服务正常。

## 6. 回滚

```bash
adb shell "rm -rf /webs && cp -a /data/webs.bak.<时间戳> /webs"
adb shell "cp -a /data/webs.bin.<时间戳> /usr/bin/webs"
adb shell "cp -a /data/libgo.so.<时间戳> /usr/bin/libgo.so"
adb shell "systemctl restart webs.service"
```

## 7. 注意事项

1. 本版 **没有** `/fibo/fibologin` 路由，`libgo.so` 只导出 `websFiboapiOpen`；不要与 `WEBUI_V_02.02.10`（含 fibologin）混用，只换前端会导致登录/接口不匹配。
2. 必须整套替换 `/webs`、`/usr/bin/webs`、`/usr/bin/libgo.so`、`route.txt`。
3. 80/443 与 lighttpd 冲突时需先停用。
4. FM150AE 平台不适用；若目标没有原厂 Web 栈，请使用 `fibocom-webui-inmodem`。
5. 前端为双构建，删除旧构建会降低旧浏览器兼容性，不建议精简。
6. `/webs` 依赖目标可写（overlay 或可写分区）。
