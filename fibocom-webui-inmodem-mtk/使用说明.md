# Fibocom 模组内置原厂 WebUI（fibocom-webui-inmodem）使用说明

## 1. 项目作用

把原厂 WEBUI（`WEBUI_V_02.02.28`，104 个站点文件）通过 **adb** 安装到模组 Linux 内部，并自带一个纯 Go 静态后端：

- 提供 `/` 静态页面与 SPA 回退；
- 实现 `/fibo/webapi`（JSON-RPC）与 `/fibo/fibologin/`；
- 通过模组内部 AT 通道读取/设置模组状态；
- 绑定 `0.0.0.0`，不依赖互联网，路由模式、网桥/透传模式下只要 PC/CPE 拿到地址即可访问；
- **FM350 专用补全**：模组本身没有路由模式、网桥模式、自动拨号和 DHCP，后端内置网络管理器会在模组内补齐自动拨号、NAT 路由、IP 透传和 DHCP 地址下发。

因此它 **不依赖** 原厂固件里的 QCMAP、goahead、lighttpd 或 `libfibosocket`，可以直接装到没有内置 Web 的模组上。

## 2. 适用模组

| 模组 | 平台/架构 | 状态 | 说明 |
|---|---|---|---|
| FM350-GL | MTK T700 / OpenWrt / ARM64 | 适配 | 原厂无路由、无网桥、无自动拨号、无 DHCP，由本项目补全 |
| FG132 | ARMv7 / ARM64 | 适配 | 5G RedCap，AT 指令按标准 3GPP + GT 回退处理 |
| FM150 | ARMv7 | 适配 | 常见 AT 通道 `/dev/smd9` |
| FM160 | ARMv7 / ARM64 | 适配 | 常见 AT 通道 `/dev/smd11`、`/dev/smd9` |
| FM190 | ARMv7 / ARM64 | 适配 | 同上 |

其他 Fibocom 模组只要满足“可 adb root、有可写持久分区（`/data`、`/usrdata` 等）、Linux 内能打开 AT 通道”，也可以安装；程序不锁定型号。

### 2.1 FM350-GL 固件事实（来自 `FM350GL-root.squashfs`）

- OpenWrt 根文件系统（squashfs）+ `mount_all` 挂载 `/data`（yaffs2，持久可写），根分区只读。
- 默认 runlevel 的 `/etc/init.d/network` 整段被注释，netifd 未启用；`/etc/config/network` 为空。
- 镜像内 **没有** `dnsmasq`/`udhcpd` 等 DHCP 服务端，也 **没有** `iptable_nat`、`nf_nat`、`xt_MASQUERADE` 等 NAT 模块。
- 对外 USB 复合设备默认包含 RNDIS（`AT+GTUSBMODE` 40/41），PC 侧网卡 MAC 固定为 `00-00-11-12-13-14`，模组侧对应 `eth0`；但不会自动下发 IP。
- AT 服务由 `atcid` 持有 `/dev/ttyGS3`，并开放 Unix socket `/dev/atci-service`。
- 数据面：自动/手动执行 `AT+CGACT` 后，`mtk_netagent` 负责 `ccmni0` 等网卡的地址与路由。

## 3. 前置条件

1. `adb devices` 能看到设备，且具有 root 权限（多数模组 `adb root` 后即为 root）。
2. 模组内有可写且可执行的分区：FM350 优先 `/data`，其他模组优先 `/usrdata`，其次 `/data`、`/mnt/data`、`/home/root`、`/userdata`、`/opt`。
3. 目标端口空闲：默认按 `80 → 8080 → 8000 → 8088` 自动选择（FM350 的 thttpd 默认未启动，80 通常空闲）。
4. AT 通道未被其他常驻程序独占；FM350 优先使用 `/dev/atci-service`。

## 4. 安装方法

### 4.1 一键安装（推荐）

在 Windows 项目根目录：

```powershell
# 1) 构建 ARMv7/ARM64 二进制并组装 dist（也可直接双击 build.bat）
powershell -ExecutionPolicy Bypass -File .\build.ps1

# 2) 推送并安装
powershell -ExecutionPolicy Bypass -File .\tools\push.ps1

# 多设备或指定端口
powershell -ExecutionPolicy Bypass -File .\tools\push.ps1 -Serial <序列号> -Port 80
```

`push.ps1` 会自动识别 `uname -m`，只推送匹配的二进制，并逐文件推送 `www`，避免不同 adb 版本目录嵌套问题。

### 4.2 手动安装

如果不用 `push.ps1`，建议按“先建目录、再逐文件推送”的方式，避免不同 adb 版本对目录推送多套一层：

```powershell
adb root
adb shell "rm -rf /data/local/tmp/fiboweb-install; mkdir -p /data/local/tmp/fiboweb-install/bin /data/local/tmp/fiboweb-install/www"
adb push dist\bin\fiboweb-arm64 /data/local/tmp/fiboweb-install/bin/
adb push dist\install.sh /data/local/tmp/fiboweb-install/
adb push dist\uninstall.sh /data/local/tmp/fiboweb-install/

$www = (Resolve-Path "dist\www").Path
Get-ChildItem "dist\www" -Recurse -Directory | ForEach-Object {
    $rel = $_.FullName.Substring($www.Length).Replace('\','/')
    adb shell "mkdir -p '/data/local/tmp/fiboweb-install/www$rel'"
}
Get-ChildItem "dist\www" -Recurse -File | ForEach-Object {
    $rel = $_.FullName.Substring($www.Length).Replace('\','/')
    adb push $_.FullName "/data/local/tmp/fiboweb-install/www$rel"
}

adb shell sh /data/local/tmp/fiboweb-install/install.sh
```

安装脚本会把程序放到 `<安装目录>/bin/fiboweb`，站点放到 `<安装目录>/www`（FM350 为 `/data/fibocom-webui`，高通模组通常为 `/usrdata/fibocom-webui`），并生成：

| 文件 | 作用 |
|---|---|
| `<安装目录>/etc/listen` | 监听地址（默认 `auto`） |
| `<安装目录>/etc/port` | 实际监听端口 |
| `<安装目录>/etc/config.json` | AT 通道、语言、时区、短信中心、网络模式/APN/DHCP |
| `<安装目录>/bin/fibowebctl` | start/stop/restart/status |
| `<安装目录>/var/fiboweb.log` | 运行日志 |

## 4.3 图形化管理工具（GUI）

项目根目录提供 Windows 图形化操作界面，封装的仍是同一套 `build.ps1` / `push.ps1` / `fibowebctl`，适合不熟悉命令行的场景。

启动方式（任选其一）：

- 双击 `启动GUI.bat`：优先启动已打包的 `FibocomWebUI.exe`，没有 exe 时用 Python 运行源码；
- 直接双击 `FibocomWebUI.exe`；
- 源码运行：`python gui\fiboweb_gui.py`（需要 Python 3 与 tkinter，Windows 官方 Python 自带）。

主要功能：

| 功能区 | 功能 |
|---|---|
| 设备连接 | 自动列出 adb 设备、刷新、显示型号与授权状态 |
| 安装设置 | 监听端口（自动/80/8080/8000）、卸载时是否保留配置 |
| 操作 | 一键安装、重新构建并安装、打开管理页、启动/停止/重启、刷新状态、查看日志、卸载 |
| 状态面板 | 安装状态、WebUI 版本、实际端口、AT 通道、模组架构、网络模式、访问地址 |
| 工具 → 网络模式 | 路由模式（NAT）、网桥/透传模式、关闭网络、自动拨号开/关 |
| 日志 | 实时显示 adb/构建/安装输出，支持清空 |

使用流程：

1. USB 连接模组，确认 `adb devices` 状态为 `device`；
2. 点击“刷新”，在下拉框选择设备；
3. 选择监听端口，点击“一键安装”（`dist` 不存在时会自动先构建）；
4. 点击“打开管理页”：工具会先执行 `adb forward`，再打开 `http://127.0.0.1:<本地端口>/`，**电脑与模组不在同一网段也能访问**；
5. FM350 可在“工具 → 网络模式”切换路由/网桥，并开启自动拨号；
6. 需要时使用启动/停止/重启、查看日志、卸载。

打包为单文件 exe（可选，需要 PyInstaller）：

```powershell
powershell -ExecutionPolicy Bypass -File .\gui\build_exe.ps1
# 产物：项目根目录 FibocomWebUI.exe
```

说明：exe 需与 `dist`、`build.ps1`、`tools\push.ps1` 位于同一项目根目录；GUI 不内嵌站点与 ARM 二进制，安装时使用项目内已构建的 `dist`。

## 5. FM350 网络能力补全（自动拨号 / 路由 / 网桥 / DHCP）

FM350 的原厂固件只负责“模组通信”，不具备 CPE 常见的网络功能。后端启动后会自动运行网络管理器（每 8 秒巡检一次），在模组内部完成以下能力。

### 5.1 自动拨号

1. 按配置执行 `AT+CGDCONT=<cid>,"IPV4V6","<APN>"`（可选 `AT+CGAUTH` 账号密码）；
2. 执行 `AT+CGATT=1`、`AT+CGACT=1,<cid>` 激活 PDP；
3. 用 `AT+CGCONTRDP=<cid>` 读取地址、网关、DNS（失败时回退 `AT+CGPADDR`）；
4. 若网卡侧已有地址（`mtk_netagent` 已配置 `ccmni0`），直接采用网卡地址；
5. 失败按 8s 起指数退避（最长 90s）重试，成功后停止重试。

APN 留空时沿用模组当前 `AT+CGDCONT` 配置，适合“无法改 APN”的工况（例如 `cbnet`）。

### 5.2 路由模式（NAT）

- 把 LAN 网卡（FM350 为 `eth0`，也可按 MAC `00:00:11:12:13:14` 自动识别）配置为 `192.168.8.1/24`；
- 写 `/proc/sys/net/ipv4/ip_forward=1`；
- 添加 `MASQUERADE`、`FORWARD ACCEPT`、`TCPMSS clamp` 规则（幂等，已存在则跳过）；
- 未联网时仍保留 LAN 地址与 DHCP，保证 PC 能先拿到 `192.168.8.x` 并打开 WebUI。
- **重要限制**：FM350 镜像缺少 `iptable_nat`/`nf_nat`/`xt_MASQUERADE`。运行时会先探测 `iptables -t nat -L -n`；若不可用，路由模式会自动回退到“透传模式”并在状态里标注，避免误以为 NAT 已生效。

### 5.3 网桥 / 透传模式

FM350 的蜂窝接口不是二层以太网，无法真正与 `eth0` 做二层桥接，因此该模式实现为 **IP 透传**（与 Windows 拨号脚本一致）：

- 不配置 `192.168.8.1`，不做 NAT；
- DHCP 把 PDP 分配的地址直接下发给第一台 PC/CPE（含运营商网关与 DNS）；
- 适合 CPE 路由器直接接管公网地址的场景。

### 5.4 内置 DHCP 服务器

纯 Go 实现，不依赖 `dnsmasq`/`udhcpd`，直接绑定 LAN 网卡（`SO_BINDTODEVICE`）：

| 项目 | 路由模式 | 网桥/透传模式 |
|---|---|---|
| 下发地址 | `192.168.8.100 ~ 192.168.8.200` | PDP 地址（单地址） |
| 网关 | `192.168.8.1` | `AT+CGCONTRDP` 网关（缺省为同网段 `.1`） |
| DNS | 运营商 DNS，缺省 `8.8.8.8 / 1.1.1.1` | 同左 |
| 掩码 | `255.255.255.0` | PDP 掩码，缺省 `/24` |
| 租期 | 12 小时（可改） | 12 小时（可改） |

支持 DISCOVER/OFFER/REQUEST/ACK/RELEASE，租约可在 `GetDhcpLeases` 查询。

### 5.5 配置项（`etc/config.json` 的 `net` 字段）

| 字段 | 默认 | 说明 |
|---|---|---|
| `mode` | `route` | `route` 路由/`bridge` 网桥透传/`off` 关闭 |
| `auto_dial` | `true` | 是否自动拨号 |
| `apn` | 空 | APN；空表示沿用模组现有配置 |
| `user` / `pass` / `auth` | 空/0 | 鉴权账号、密码与类型（0 无、1 PAP、2 CHAP） |
| `pdp_type` | `IPV4V6` | `IPV4`/`IPV6`/`IPV4V6` |
| `cid` | `1` | PDP 上下文编号 |
| `lan_iface` / `wan_iface` | 自动 | 手动指定 LAN/WAN 网卡 |
| `lan_ip` | `192.168.8.1` | 路由模式 LAN 地址 |
| `pool_start` / `pool_end` | `192.168.8.100/200` | DHCP 地址池 |
| `lease_hours` | `12` | 租期（小时） |
| `dns1` / `dns2` | 空 | 覆盖运营商 DNS |

### 5.6 相关接口

| 方法 | 说明 |
|---|---|
| `GetNetworkMode` / `SetNetworkMode` | 读取/切换模式，可同时设置 APN、自动拨号、LAN 地址、地址池等 |
| `GetDHCPSettings` / `SetDHCPSettings` | 原厂 LAN/DHCP 页面读写（LAN 地址、地址池、租期、DNS） |
| `GetDhcpLeases` | 当前 DHCP 租约 |
| `GetEthnetInfo` | LAN/WAN 端口连接状态 |
| `DialNow` / `Hangup` | 立即拨号 / 断开 |
| `GetWANInfo` | 原厂 WAN 页面：连接状态、地址、网关、DNS、时长 |
| `GetConnectionSettings` / `SetConnectionSettings` | APN、鉴权、PDP 类型 |
| `GetMobileDataStatus` / `SetMobileDataStatus` | 移动数据开关（内部转为拨号/断开） |
| `GetNetworkSettings` / `SetNetworkSettings` | 自动/手动选网、锁频段（`AT+GTACT`） |

`GET /fiboweb/status` 的 `net` 字段会返回模式、LAN/WAN 网卡与地址、网关、DNS、NAT 是否可用、DHCP 是否运行、租约数、当前状态。

## 6. 开机自启

安装脚本按目标系统自动选择：

1. **systemd**（`/run/systemd/system` 存在）：写入 `/etc/systemd/system/fiboweb.service`，`systemctl enable/restart`。
2. **OpenWrt procd**（`/etc/rc.common`、`/etc/init.d` 存在，FM350 属于此类）：写入 `/etc/init.d/fiboweb`，procd 托管，`/etc/init.d/fiboweb enable` 生成 `/etc/rc.d/S99fiboweb`。
3. **其他**：向 `/etc/rc.local` 追加启动块；若 `/etc` 只读，则仅本次启动并给出提示。

FM350 的 `/etc` 在 squashfs 上只读，但 OpenWrt 启动后会通过 overlay 变为可写；若仍不可写，请先 `mount -o remount,rw /` 再安装。

## 7. 访问与验证

安装结束会打印实际端口与所有可用 IP，例如：

```text
http://192.168.8.1/
http://192.168.8.1:8080/
```

FM350 组网后，PC/CPE 通过本项目 DHCP 自动获得：

- 路由模式：`192.168.8.100` 起，网关 `192.168.8.1`；
- 网桥/透传：运营商地址，网关为运营商网关。

常用检查：

```sh
/data/fibocom-webui/bin/fibowebctl status
cat /data/fibocom-webui/etc/port
cat /data/fibocom-webui/var/fiboweb.log
```

也可以直接请求：

```text
http://<模组IP>:<端口>/fiboweb/status
```

返回内容包含型号、AT 通道、端口、IP 列表、运行时长与 `net` 网络状态。若 AT 通道探测失败，可现场执行：

```sh
/data/fibocom-webui/bin/fiboweb -selftest -state /data/fibocom-webui/etc
```

## 8. 端口与网络行为

- 服务固定绑定 `0.0.0.0`，路由模式从 LAN 口访问，网桥/透传模式从透传地址访问。
- 端口自动选择：80（无冲突时与原厂地址一致）→ 8080 → 8000 → 8088。
- FM350 的 thttpd 默认未启动，80 通常可用；若被占用会自动落到 8080。
- 安装脚本会按网卡放行实际端口（含非私网来源，适配透传公网地址），并放行 LAN 网卡的 DHCP（UDP 67）。
- 完全离线可用，不加载任何外部 CDN。

## 9. 卸载

```powershell
adb shell sh /data/local/tmp/fiboweb-install/uninstall.sh
```

可选：`KEEP_DATA=1` 保留配置与日志；`FIBOWEB_ROOT=/data/fibocom-webui` 指定安装目录。卸载会停止服务、删除 `/etc/rc.d/S99fiboweb`、`/etc/init.d/fiboweb` 与相关 iptables 规则。

## 10. 注意事项

1. **AT 通道**：默认依次探测 `/dev/atci-service`（Unix socket）、`/dev/ttyGS3/GS2/GS0/GS1`、`/dev/smd11`、`/dev/smd9`、`/dev/smd7`、`/dev/smd8`、`/dev/smd10`、`/dev/smd6`、`/dev/smd5`、`/dev/at_mdm0`、`/dev/at0`、`/dev/ttyHS0`、`/dev/ttyMSM0`、`/dev/ttyACM0`。可用 `FIBOWEB_AT=/dev/atci-service`（或 `unix:/dev/atci-service`）或修改 `etc/config.json` 覆盖。
2. **不要抢占主机 AT**：FM350 的 `/dev/ttyGS3` 由 `atcid` 持有，优先走 `/dev/atci-service`，避免与电脑侧 AT 工具冲突。
3. **SELinux**：FM150 等模组可能是 Enforcing；若服务未监听端口，可先 `setenforce 0` 验证是否为策略拦截，正式环境需自行添加策略。
4. **只读根分区**：FM350 根分区只读，安装脚本依赖 overlay 提供的可写 `/etc`；若不可写则无法安装开机自启，本次仍会启动。
5. **NAT 缺失**：FM350 镜像未带 NAT 模块时，路由模式会自动回退透传，属固件限制，不是本项目故障。
6. **升级/刷机**：前端中的在线升级页面返回“不支持”，请使用厂商升级工具。
7. **登录**：站点已做本地会话注入，打开即进入 `#/Home`，并取消了 10 分钟自动注销。
